# ReFlux: exit-ноды на своём сервере

ReFlux запускает на одном Linux-сервере с Docker по отдельной exit-ноде OpenFlux
на каждого клиента. Трафик клиентов выходит в интернет только через
AmneziaWG-туннели и никогда не уходит с адреса самого сервера.

```
клиент ──документ mail.ru──▶ [reflux-node-<имя>] ─┐  общая сеть
клиент ──документ mail.ru──▶ [reflux-node-<имя>] ─┤
                                                   ▼
                       [reflux-egress: kill switch, DNS-over-TLS]
                          ├─ awg-ru    российские адреса (и mail.ru)
                          └─ awg-world всё остальное, с резервными серверами
```

- **Один клиент — один канал:** свой документ, свой ключ, свой контейнер.
  Нода обслуживает одного активного клиента, поэтому документ нельзя делить.
- **Ноды** работают в режиме `l4` без привилегий, файловая система только для
  чтения, портов наружу не открывают. Своей сети у них нет: они в сети egress.
- **Egress** держит два туннеля: `ru-1.conf` для российских адресов (список
  сетей из статистики RIPE, обновляется раз в сутки) и `world-N.conf` для
  остального. Вместо российского туннеля можно выпускать Россию напрямую
  через провайдера сервера (см. «Россия напрямую»). Если мировой туннель не отвечает 30 секунд, egress переходит на
  следующий `world-N.conf` и не возвращается на прежний сам. Если упал
  российский туннель, российский трафик стоит до его восстановления.
- **Kill switch:** из контейнера наружу выпускается только UDP к серверам
  AmneziaWG. Нет туннеля — нет трафика.
- **DNS:** `unbound` в egress, проверка DNSSEC, запросы к Quad9 и Cloudflare
  по TLS через мировой туннель. Домены транспортов (`mail.ru`,
  `datacloudmail.ru`, `yandex.ru`, `yandex.net`) спрашиваются у DNS Яндекса
  через российский туннель: документ mail.ru продолжает работать, даже когда
  мировой туннель лежит.

## Установка (один раз)

Нужны Docker с плагином compose и модуль ядра `amneziawg` на хосте
(пакет `amneziawg-dkms`). Проверка: `grep amneziawg /proc/modules`.

1. **Правило маршрутизации.** Если трафик самого сервера идёт через свой VPN
   (у нас `awg0`), туннели egress должны идти мимо него:
   ```sh
   sudo cp deploy/reflux/host/reflux-egress-route.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now reflux-egress-route
   ip rule   # первой после 0: строка 100: from 172.31.250.0/24 lookup main
   ```
   Без этого правила `reflux apply` откажется запускать egress.

2. **Утилита `reflux`** из релиза `reflux-v*` (проверьте сумму по `SHA256SUMS`):
   ```sh
   install -m 0755 reflux-linux-amd64 ~/.local/bin/reflux
   ```

3. **Конфиги AmneziaWG** в `~/reflux/egress/` с правами `600`:
   - `ru-1.conf` — сервер в России;
   - `world-1.conf`, `world-2.conf`, … — остальной мир, в порядке переключения.

   Каждый конфиг должен быть выдан только для этого сервера: один ключ
   AmneziaWG не работает на двух устройствах сразу. Одновременно открыты ровно
   два подключения: российское и одно мировое.

4. **Запуск egress** и проверка:
   ```sh
   reflux apply
   reflux status
   ```
   В выводе `status` обе строки `world` и `russia` должны быть `up`.

## Клиенты

```sh
reflux add phone --transport mailru --url https://cloud.mail.ru/public/XXXX/YYYY
reflux list
reflux show phone            # данные для клиента ещё раз
reflux revoke phone          # остановить ноду и удалить ключ
reflux logs phone | reflux logs egress
```

На каждого клиента нужен **новый** документ mail.ru, открытый по ссылке.
Ссылки с символами `#`, `;` и пробелами не принимаются: `.conf` ядра их обрезает.

`add` и `show` печатают:
- поля для ручного ввода (транспорт, ссылка на документ, ключ шифрования,
  Legacy codec выключен): для приложений без импорта ссылок, например
  damnurmum/OpenFlux-Android;
- ссылку `openflux://` и QR-код: для приложений OpenFlux с импортом.

Ссылка и ключ дают доступ к каналу: передавайте их только его владельцу.
`revoke` удаляет ключ навсегда; запись о канале остаётся в `~/reflux/revoked/`.

## Россия напрямую

```sh
touch ~/reflux/egress/ru-direct && chmod 600 ~/reflux/egress/ru-direct
reflux restart
```

Российские адреса (и документ-транспорт mail.ru) уходят через провайдера
сервера, без туннеля; `ru-1.conf` не нужен, у провайдера AmneziaWG занято одно
подключение. Kill switch выпускает мимо туннеля только российские префиксы.
Цена: российские сайты и mail.ru видят домашний IP сервера. Выигрыш на нашем
сервере: канал через mail.ru с ~0,05 до ~3 МБ/с, потому что российский
AWG-сервер давал ~1 Мбит/с. Вернуть туннель: удалить файл и `reflux restart`.

## Обслуживание

| Команда | Что делает |
|---|---|
| `reflux update` | скачивает новые образы и перезапускает изменившиеся контейнеры |
| `reflux restart` | пересоздаёт egress и все ноды |
| `reflux heal` | пересоздаёт только ноды, оставшиеся без сети после перезапуска egress |
| `reflux apply --dry-run` | только переписывает `~/reflux/compose.yml` |

Если контейнер egress перезапустился (сбой, обновление Docker), ноды остаются в
его старой сети, где нет выхода наружу. `reflux heal` находит такие ноды и
пересоздаёт только их; поставьте его в cron пользователя (`crontab -e`):

```
* * * * * $HOME/.local/bin/reflux heal >> $HOME/reflux/heal.log 2>&1
```

**Известная проблема (код OpenFlux, не ReFlux):** если нода перезапущена
(`reflux restart`, `update`, `heal`), уже подключённый клиент может не
переподключиться сам: нода слышит его, а он её — нет. Помогает переподключение
на клиенте (выключить и включить VPN в приложении).

Сразу после перезапуска egress мировой туннель может 1–3 минуты перебирать
серверы: сервер провайдера, к которому egress был подключён перед
перезапуском, какое-то время принимает рукопожатие, но не пропускает данные.
Egress сам переходит к следующему `world-N.conf`. Российский туннель так не
делает.

`reflux status` показывает, сколько пакетов остановил kill switch: это
попытки выйти мимо туннелей. В нормальной работе там 0.

После обновления ядра убедитесь, что DKMS пересобрал модуль:
`grep amneziawg /proc/modules`. Без модуля egress не поднимет туннели и
трафик клиентов остановится (не утечёт).

## Проверка, что всё идёт через туннели

```sh
docker exec reflux-egress wget -qO- https://api.ipify.org   # IP текущего мирового сервера
docker exec reflux-egress ip route get 77.88.8.8            # ... dev awg-ru: Россия в российский туннель
docker exec reflux-egress ip route get 9.9.9.9              # ... dev awg-world: остальное в мировой
```

IP сервера (`curl https://api.ipify.org` на самом хосте) не должен совпадать с
тем, что видит egress.
